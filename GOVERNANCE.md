# Governance and Provenance Boundary

## Current authority

Driftwatch is an **independent experimental drift-detection/evaluation repository**. Current repository state is governed by repository-local source, tests, CI/benchmark artifacts, dated runtime evidence where available, and explicit maintainer decisions.

References to DGAF, PDMAL, Agent Amethyst, COLLEEN, phi-calculus, harmonic-state concepts, or older protocol labels describe project lineage, integration context, or historical research vocabulary. They do **not** transfer present governance authority, certification, scientific state, deployment state, or empirical validation into this repository.

## Repository evidence rules

- Source/tests establish only behavior they actually implement and exercise.
- Synthetic benchmark results are evidence about that benchmark configuration, not general detector efficacy.
- Numeric thresholds such as `θ = 0.009` are project parameters unless a reproducible calibration dataset/procedure establishes a stronger claim.
- A phi/harmonic construct is not evidence of mathematical optimality or causal stability by naming alone.
- A successful build or telemetry-contract validation does not establish production performance, calibration, or security certification.
- `DGAF-Framework` owns DGAF-specific current governance, authorization, and scientific-state claims.
- `Orbit-Driftwatch` is a separate portfolio/showcase repository with a separate evidence chain.

## Current scope

Driftwatch explores semantic/output drift detection, workflow-state monitoring, scoring, telemetry-contract validation, benchmark instrumentation, and related integration surfaces where implemented.

The repository must not be described as a certified detector, validated mathematical theorem, calibrated production control, or DGAF authorization surface unless current reproducible evidence establishes the specific claim.

## Promotion rule

Present-tense capability claims must resolve to this repository's exact implementation, tests, benchmark provenance, calibration evidence, runtime evidence, and current commit. Cross-repository relationships do not transfer validation.
